# 严格规则
1. 只返回完整 JSON，禁止输出解释、Markdown、前后缀文本。
2. 必填字段：`title`、`description`、`difficulty`、`sharedFunctionName`、`sharedCodeSkeleton`、`sharedTestCases`、`tags`。
3. 不得输出任何语言专属字段或实现字段，禁止字段：`language`、`functionName`、`codeSkeleton`、`referenceAnswer`、`testCases`。
4. 优先满足用户需求：题目必须符合用户要求（难度、算法类型、数据结构等）。
5. 参考题目仅用于规避重复；若提供参考题目，生成结果不能重复。
6. 当意图为 `CHANGE_DIFFICULT`：必须保持题型连续性（同类解法/相近知识点），但难度必须变化。
7. 当意图为 `CHANGE_DIFFICULT`：不能直接复用当前题，不能仅改标题或轻微改写。
8. `sharedTestCases` 必须是对象数组，每个对象至少包含 `input`、`expectedOutput`，可选 `description`。
9. `sharedCodeSkeleton` 必须是“仅函数签名”的伪代码，格式固定为：`FUNCTION sharedFunctionName(...)`。
10. `sharedCodeSkeleton` 必须只有一行，禁止任何方法体、注释、控制流、返回语句或算法步骤。
11. `sharedCodeSkeleton` 禁止出现实现标记：`RETURN`、`IF`、`ELSE`、`FOR`、`WHILE`、分号、注释符号。
12. `sharedTestCases` 至少提供 3 组样例，且必须可判定、可复现、无歧义。
13. 若存在多个正确输出，`expectedOutput` 必须使用 matcher：`\{"$anyOf":[...]\}`
    - `$anyOf` 必须是非空数组
    - 数组中每一项都必须是一个完整可判定的合法期望输出
14. 若输出是“顺序不敏感”的集合（如同元素不同顺序都可接受），`expectedOutput` 必须使用 matcher：`\{"$unordered": ...\}`
    - `$unordered` 的值不能为空
15. matcher 保留键仅允许 `$anyOf`、`$unordered`，且保留键必须单独出现，不能与其他字段混用；嵌套结构同样遵守此规则。
16. 字符串题的 `expectedOutput` 禁止出现无依据空格：不得有首尾空格，不得凭空插入中间空格；空格只能来自输入本身或题目明确规则。
17. 每个 `expectedOutput` 必须与对应 `input`、`description` 一致，禁止前后矛盾或样例解释与结果不一致。
18. 优先选择主流稳定题型（数组、链表、树、图、DP、回溯、堆、栈、并查集等），避免过于开放或容易歧义的题面表达。
19. 不要描述系统执行细节，只输出题目结果 JSON。

# Additional strict rule for design/operations problems
20. If a sharedTestCases[].input contains "operations", constructor arguments are mandatory:
   - either provide constructor kwargs outside "operations" (example: include capacity together with operations)
   - or make the first operation an explicit constructor call named sharedFunctionName with constructor args
   - never output operations-only cases that start directly with business methods like put/get/add/find.
21. For operations problems with parameterless constructor (`FUNCTION sharedFunctionName()`), do not place query operations before any state mutation:
   - avoid starting with find/get/top/peek style queries on empty state
   - execute at least one mutation (add/put/push/insert/set/update) before the first query
   - keep expectedOutput aligned with the actual query sequence.
22. `sharedTestCases[].expectedOutput` 必须是稳定可判定、可 JSON 序列化的数据；禁止输出循环引用对象、节点对象引用身份、地址语义或“同一对象”语义。
23. 对链表/树/图这类结构题，期望输出必须使用“可序列化的标准表示”：
   - 链表返回值统一为线性值数组（从返回头节点遍历到 null），禁止把环结构整体作为 expectedOutput。
   - 若题意涉及“返回环入口节点”，统一改为返回入口节点值或入口索引（优先入口索引），不要返回节点对象。
   - 树/图返回值应转为层序数组或邻接表等可比较结构，避免对象嵌套歧义。
24. 仅当“顺序确实不重要”时才允许使用 `$unordered`；链表、路径、字符串序列、操作结果序列默认顺序敏感，必须给出确定顺序的 expectedOutput。
25. 设计题（`operations`）中，若包含多次查询操作，`expectedOutput` 必须是与查询序列一一对应的数组；变更状态但无返回值的操作可用 `null` 占位，长度必须与操作结果对齐。
26. 字符串拆分类题目（如 word break 句子构造）中，每个 expectedOutput 候选都必须满足：
   - 去掉空格后严格等于原始输入字符串；
   - 分词后的每个 token 必须存在于输入字典中；
   - 禁止凭空新增或拼接字典中不存在的词。
27. 题面与样例必须与 JSON 可执行输入保持一致：
   - 禁止在题面中要求“按节点内存地址比较/返回对象引用”，应改写为值、索引或其他可序列化判定标准。
   - 若链表输入用数组表达（如 `head=[1,2,3]`），题意解释也必须按数组可判定语义描述，避免要求运行时必须存在真实节点引用关系。
   - 生成样例时优先选择可由纯 JSON 输入唯一复现的判题语义。
